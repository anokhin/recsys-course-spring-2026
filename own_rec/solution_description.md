В данной работе была использована модель DSSM (Deep Structured Semantic Model), но с важными архитектурными изменениями.

## Архитектурные изменения DSSM

Базовая двухбашенная архитектура была расширена двумя ключевыми компонентами: механизмом внимания в user tower и logQ-коррекцией функции потерь.

### User Tower с Recency-Weighted Attention

В базовом DSSM пользовательский вектор получается простым взвешенным суммированием эмбеддингов треков из истории. В данной работе вместо этого используется механизм внимания, учитывающий два фактора одновременно: давность прослушивания и время прослушивания трека.

Веса внимания вычисляются по формуле:

$$a_i = \frac{\exp(-\lambda \cdot (L - 1 - i)) \cdot \tau_i}{\theta}$$

где $\lambda$ — обучаемый параметр затухания (recency decay), $\tau_i$ — нормализованное время прослушивания $i$-го трека в истории, $\theta$ — обучаемая температура внимания. Итоговые веса получаются через softmax с маскировкой паддинга, что не позволяет пустым позициям влиять на результат:

$$w_i = \frac{\exp(a_i) \cdot \mathbf{1}[i \neq \text{pad}]}{\sum_j \exp(a_j) \cdot \mathbf{1}[j \neq \text{pad}]}$$

Финальный вектор пользователя — нормализованная взвешенная сумма эмбеддингов:

$$\mathbf{u} = \text{normalize}\!\left(\sum_{i=1}^{L} w_i \cdot \mathbf{e}_i\right)$$

Параметры $\lambda$ и $\theta$ обучаются вместе с весами модели, что позволяет модели самостоятельно подобрать оптимальный баланс между рецентностью и качеством прослушивания. По итогам обучения $\lambda \approx 1.0$, что соответствует сильному акценту на последних треках истории.

### Item Tower

Item tower намеренно оставлен простым: отдельная матрица эмбеддингов `item_emb` размера `num_items × D`, не разделяющая веса с `user_emb`. Разделение весов позволяет user tower и item tower формировать разные геометрические пространства, что улучшает качество разделения пользовательских предпочтений и контента.

### LogQ-коррекция функции потерь

При обучении с популярностно-смещёнными негативными примерами модель систематически штрафует популярные треки сильнее, чем необходимо, поскольку они чаще попадают в выборку негативов. Для устранения этого смещения применяется logQ-коррекция, предложенная в работе по YouTube DNN:

$$s^*_{\text{pos}} = \frac{\mathbf{u} \cdot \mathbf{v}_+}{T} - \log q(v_+), \quad s^*_{\text{neg}} = \frac{\mathbf{u} \cdot \mathbf{v}_-}{T} - \log q(v_-)$$

где $q(v)$ — частота айтема в обучающих данных, $T = 0.07$ — температура. Итоговый лосс — взвешенный BPR:

$$\mathcal{L} = -\frac{\sum_i w_i \cdot \frac{1}{|N|}\sum_{j \in N} \log \sigma(s^*_{\text{pos},i} - s^*_{\text{neg},j})}{\sum_i w_i}$$

где вес примера $w_i = 1 + 2 \cdot \tau_{\text{target}}$ масштабируется по времени прослушивания целевого трека.

### Схема архитектуры

```
История сессии (ctx)            Целевой / негативный трек
[t_1, t_2, ..., t_L]           [v_+]  [v_-1, ..., v_-K]
         │                           │           │
   user_emb (D)              item_emb (D)  item_emb (D)
         │                           │           │
  Recency Decay (λ)           normalize     normalize
  Listen Time (τ)                   │           │
         │                         v_+         v_-
  Attention Weights (softmax)       │           │
         │                          └─────┬─────┘
  Weighted Sum                            │
         │                     score = u·v/T − log q(v)
    normalize                             │
         │                      BPR loss с весами w_i
         u ───────────────────────────────┘
```
