## Homework 2 Report

### Описание

В treatment используется ранжировщик для текущей сессии с небольшой обучаемой моделью качества кандидата. Модель обучается по логам botify и оценивает ожидаемое время следующего прослушивания для кандидата в текущем состоянии сессии. В control оставлен стандартный SasRec-I2I, а в treatment сначала собирается набор кандидатов из SasRec-I2I, LightFM-I2I и персонального списка пользователя, после чего кандидаты ранжируются обученной моделью.

Основное отличие от простого смешивания готовых рекомендаций: кандидат выбирается не фиксированной формулой, а по значениям признаков, которые были оценены на логах.

### Детали

Для обучения используются только события из контрольной группы (`HSTU == C`), чтобы модель не подстраивалась под собственные рекомендации. Скрипт `script/train_user_top.py` делает две вещи.

1. Собирает `botify/data/user_top_recommendations.json`: для каждого пользователя берутся хорошо дослушанные треки, расширяются соседями из `sasrec_i2i.jsonl` и `lightfm_i2i.jsonl`, а если данных мало, список дополняется запасными рекомендациями.
2. Обучает `botify/data/session_value_model.json`: из последовательностей событий строятся переходы вида "текущее состояние сессии -> показанный кандидат -> время следующего прослушивания". Показанный трек получает реальное значение, альтернативные кандидаты из того же состояния добавляются как слабые отрицательные примеры.

Модель табличная: для каждого признака по группам считается сглаженное среднее значение целевой переменной. При рекомендации эти оценки усредняются с весами по количеству наблюдений. Используются такие признаки:

- группа времени предыдущего трека;
- источник кандидата: SasRec, LightFM, персональный список или их комбинация;
- позиция кандидата в списке похожих треков;
- был ли опорный трек последним треком или хорошим треком из текущей сессии;
- позиция в персональном списке пользователя;
- встречался ли исполнитель в текущей истории;
- среднее качество трека и исполнителя по логам.

В `botify/botify/recommenders/user_top.py` для treatment читается история пользователя из Redis, строятся кандидаты по последнему треку и нескольким лучшим трекам текущей сессии, убираются уже прослушанные треки и выбирается кандидат с максимальной оценкой модели. Если подходящих кандидатов нет, используется запасной вариант SasRec-I2I.

```text
логи botify
    -> переходы между треками
    -> признаки по группам
    -> сглаженная модель качества
    -> кандидаты из SasRec/LightFM/персонального списка
    -> лучший кандидат по ожидаемому времени прослушивания
```
