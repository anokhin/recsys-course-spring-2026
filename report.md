# Отчёт HW2: Мультиисточниковый RRF-ранкер с разнообразием по артистам

## Аннотация

Предлагается **мультиисточниковый рекомендер на основе Reciprocal Rank Fusion (RRF)**, объединяющий пулы кандидатов из SasRec-I2I, LightFM-I2I и пользовательских рекомендаций HSTU с учётом разнообразия артистов в сессии. В отличие от бейзлайна SasRec-I2I, который выбирает один случайный опорный трек и возвращает первую непрослушанную рекомендацию, наш подход агрегирует сигналы от всех недавних опорных треков с весами, пропорциональными суммарному времени прослушивания, объединяет два дополняющих друг друга I2I-источника через RRF и применяет штраф к кандидатам, чей артист уже недавно встречался в сессии. Это напрямую противодействует штрафу симулятора `artist_discount_gamma = 0.8` и повышает стабильность рекомендаций за счёт агрегации по нескольким опорным трекам.

## Описание

**Генерация кандидатов.** На каждый запрос выбирается до 5 опорных треков из истории прослушиваний пользователя, отранжированных по суммарному времени прослушивания. Для каждого опорного трека кандидаты извлекаются из SasRec-I2I (вес 1.0) и LightFM-I2I (вес 0.7). Пользовательские рекомендации HSTU (долгосрочные предпочтения, вес 0.5) добавляются независимо от опорных треков по user ID. Оценки накапливаются через RRF: каждый I2I-источник вносит `w × anchor_time / (rank + 60)`, HSTU — `w / (rank + 60)`. Уже прослушанные треки фильтруются до подсчёта оценок.

**Разнообразие по артистам.** К кандидатам, чей артист входит в 3 последних уникальных артиста сессии, применяется мягкий штраф (×0.25). Это мягкое ограничение — если все кандидаты относятся к недавним артистам, штраф применяется равномерно и лучший по оценке трек всё равно побеждает. Все обращения к артистам используют словарь `{track_id: artist}` в оперативной памяти, построенный при запуске сервера: ноль дополнительных обращений к Redis на рекомендацию.

**Почему это лучше SasRec-I2I.** У бейзлайна два слабых места: (1) он выбирает один случайный опорный трек, что вносит высокую дисперсию; (2) никак не диверсифицирует артистов, из-за чего ~19% рекомендаций SasRec повторяют одного артиста, накапливая скидки `0.8^k` на время прослушивания. Наш подход снижает дисперсию за счёт агрегации по нескольким опорным трекам и напрямую устраняет «усталость от артиста».
