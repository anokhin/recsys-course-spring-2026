# Отчёт: Улучшение Botify через онлайн‑ML HybridRecommender

## i. Abstract
В данном эксперименте я заменяю стандартное ранжирование на **гибридную онлайн‑ML модель (contextual bandit)**. Модель обучается в режиме реального времени на логах сервиса, предсказывая ожидаемое время прослушивания трека на основе текущего контекста пользователя. В качестве контрольной группы используется **SasRec‑I2I**. Гипотеза заключалась в том, что персонализированное переранжирование кандидатов с использованием механизмов exploration позволит значительно увеличить $mean\_session\_time$ за счёт лучшего подбора контента под меняющиеся интересы пользователя.

## ii. Детали
Реализованный **HybridRecommender** выступает в роли реранкера над пулом кандидатов. Кандидаты формируются из трех источников:
1.  **User-based**: персонализированные списки из HSTU.
2.  **Item-to-item**: рекомендации на основе «якорей» из недавней истории прослушивания через LightFM-i2i.
3.  **Exploration**: случайные треки для борьбы с «пузырём фильтров».

Для предсказания используется **линейная модель с SGD** и механизмом **feature hashing** (2^18 признаков). Признаки включают в себя метаданные трека (жанр, артист, страна, год), агрегаты истории пользователя (среднее время, доля скипов) и кросс-фичи (совпадение жанра/муда истории и кандидата). Модель обучается «честно»: данные о рекомендации временно сохраняются в Redis и обновляются, когда пользователь возвращает обратную связь в виде времени прослушивания на следующем запросе. Высокая производительность (снижение latency) достигнута за счёт кэширования хэшированных векторов признаков.

### Диаграмма процесса:
`history (redis)` → `candidates (HSTU + LightFM-i2i + explore)` → `features (ctx+item, hashing)` → `score` → `choose` → `log` → `SGD update (next request)`

## iii. Результаты A/B эксперимента
Эксперимент проводился по схеме: **Control = SasRec‑I2I** (`Treatment.C`), **Treatment = HybridRecommender** (`Treatment.T1`). Симуляция была запущена на **2000 эпизодах** с фиксированным сидом 3133. Скрипт `analyze_ab.py` подтвердил статистическую значимость улучшений по всем ключевым метрикам. Особенно выделяется рост времени сессии на **231%** и сокращение задержки ответа сервера почти на **100%** за счёт оптимизации вычислений.
