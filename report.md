# Homework 2 Report

## Abstract

Идея: заменить SasRec-I2I рекомендер на пользовательский HSTU-рекомендер.
SasRec-I2I рекомендует треки, похожие на только что прослушанный (item-to-item переходы).
HSTU строит персонализированный ранжированный список треков для каждого пользователя на основе всей истории.
В качестве метрики успеха — стат. значимый рост `mean_time_per_session` относительно SasRec-I2I в контроле.

## Details

SasRec-I2I не учитывает личные предпочтения пользователя — он смотрит только на текущий трек.
HSTU обучается на последовательностях прослушиваний и предсказывает, что пользователю понравится
в рамках всей сессии, учитывая его долгосрочные интересы.

Схема работы:

```
[история прослушиваний пользователя]
            │
            ▼
      ┌──────────┐
      │   HSTU   │  (оффлайн, предрасчёт)
      └──────────┘
            │
            ▼
  ранжированный список треков
            │
            ▼
  фильтрация уже услышанных треков
            │
            ▼
      top-1 непрослушанный трек
```

Реализация — `HSTURecommender` (файл `botify/botify/recommenders/hstu.py`):
- загружает предрасчитанный список из Redis по user_id
- фильтрует треки, которые уже были в текущей сессии (из истории в Redis)
- возвращает первый непрослушанный трек в порядке ранжирования
- fallback на SasRec-I2I для пользователей без HSTU-рекомендаций

A/B тест: эксперимент `HSTU`, сплит 50/50:

| Группа | Рекомендер |
|--------|-----------|
| C      | SasRec-I2I (контроль) |
| T1     | HSTURecommender       |
