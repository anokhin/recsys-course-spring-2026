# Отчёт по домашнему заданию 2

## Abstract

В качестве тритмента использую двухэтапный пайплайн: Two-Tower для генерации кандидатов и LambdaRank для переранжирования. Two-Tower обучается на duration-weighted BPR-лоссе - длинные прослушивания вносят больший вклад. LambdaRank переранжирует топ-500 кандидатов.

## Детали реализации

**Two-Tower (retrieval)** Энкодер треков: эмбеддинг артиста, multi-hot вектор жанров, one-hot вектор настроения, год выпуска, log-fans. Анчор трек кодируется query-башней, кандидат - item-башней. Позитивы - переходы, где оба трека прослушаны больше половины; хардовые негативы - треки, на которые перешли, но пропустили (прослушав anchor и скипнув target). Веса пар: `w = log1p(listen_time)`. Эмбеддинги треков индексируются в FAISS HNSW, из которого достаётся топ-500 кандидатов для реранка.

**LambdaRank** LightGBM-ранкер с `objective=lambdarank`, `ndcg@[5,10,20]`, 500 деревьев. Признаки: dot-product score из башен, same_artist, genre_overlap, same_mood, year_diff, log_fans, log_popularity, log_transition_count, log_skip_count, rank_score, diversity_penalty (штраф за повторного артиста в списке). Метки релевантности: 0 - не наблюдался, 1 - пропущен, 2 - хорошо прослушан.


```
logs -> Two-Tower -- faiss hnws --> top-500 for anchor --> LambdaRank --> learned_i2i.jsonl (top-200)
            |                                                 |
            |                                                 |
        embeddings --------------------------------------------
```
