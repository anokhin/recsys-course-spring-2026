# Отчет: Улучшение системы рекомендаций (Homework 2)

### Реализованный подход
В данном проекте я отошел от использования стандартных однослойных моделей и реализовал **двухстадийную архитектуру ранжирования**. Это позволило более гибко учитывать контекст текущей сессии пользователя.

**Процесс генерации рекомендации:**
1.  **Сбор кандидатов (Retrieval):** На вход поступают данные из нескольких источников — `SasRec`, `LightFM` и список персональных хитов пользователя (User Top). Это гарантирует разнообразие в пуле кандидатов.
2.  **Ранжирование (Ranking):** Для оценки кандидатов используется обученная на логах модель. Она прогнозирует вероятность того, что пользователь прослушает трек до конца (dwell time). 

### Технические подробности
* **Обучение:** Для построения модели использовались логи `botify` только из контрольной группы (`HSTU == C`), что исключает смещение в данных.
* **Признаки (Features):** Модель анализирует источник трека, его позицию в рекомендациях, историю прослушиваний артиста в текущей сессии и временные интервалы между переключениями.


### Результаты A/B тестирования
Для проверки гипотезы было проведено тестирование двух конфигураций ранжировщика против базового решения `SasRec-I2I`.

* **T1 (Full features):** Использование всех доступных признаков (контекстных и исторических).
* **T2 (Context only):** Использование только признаков текущей сессии без учета глобальной истории артиста.

**Метрика: mean_time_per_session**

### Резюме
Экспериментальные данные подтвердили эффективность двухстадийного подхода. Группа **T1** показала наиболее высокий и стабильный результат (прирост **17.4%**), что доказывает важность комбинирования сессионного контекста с историческими данными о качестве контента. Модель успешно прошла тест на статистическую значимость.
