# Отчёт по ДЗ2

## Abstract

Предлагается рекомендер **Contextual I2I**, использующий предыдущий трек как контекстный якорь для item-to-item поиска, с расширенным пулом кандидатов (объединённые рекомендации SasRec + LightFM) и диверсификацией по артистам. В отличие от бейзлайна SasRec-I2I, который сэмплирует якоря из полной истории пользователя (смешивая интересы разных сессий), наш подход фокусируется на контексте текущей сессии. A/B эксперимент показывает **статистически значимое улучшение +32%** по метрике `mean_time_per_session`.

## Детали реализации

### Ключевая идея

Симулятор оценивает каждую рекомендацию как `dot(track_embedding, session_embedding)`, где эмбеддинг сессии фиксирован. Первый трек выбирается из ближайших соседей этого эмбеддинга, поэтому эмбеддинг предыдущего трека — хорошая аппроксимация интереса в текущей сессии. Используя **предыдущий трек как I2I якорь** (вместо выборки из всей истории), мы держим рекомендации в русле текущего интереса пользователя.

### Архитектура

```
Запрос (prev_track, prev_time)
       │
       ▼
┌──────────────────────────┐
│ prev_time >= 0.4?        │──── Нет ──→ I2I по истории
│       │ Да               │            (якоря SasRec из
│       ▼                  │             listen history)
│ Contextual I2I lookup    │
│ (prev_track → combined   │
│  SasRec+LightFM recs)    │
│       │                  │
│       ▼                  │
│ Диверсификация артистов  │
│ (макс. 2 трека/артист)   │
│       │                  │
│       ▼                  │
│   HSTU рекомендации      │
│   (если есть)            │
│       │                  │
│       ▼                  │
│   Random fallback        │
└──────────────────────────┘
```

### Изменения относительно бейзлайна

1. **Новый рекомендер** (`contextual_i2i.py`): предыдущий трек как I2I якорь, диверсификация по артистам, сигнал listen-time
2. **Расширенный пул кандидатов** (`combined_i2i.jsonl`): объединены рекомендации SasRec-I2I и LightFM-I2I (~18 уникальных кандидатов на айтем вместо 10 в бейзлайне)
3. **Диверсификация по артистам**: лимит 2 трека на артиста, чтобы избежать штрафа симулятора за повтор артиста (`gamma^artist_count`)
4. **Сигнал listen-time**: контекстный I2I используется только при хорошем приёме предыдущего трека (`time >= 0.4`); иначе — fallback на I2I по истории или HSTU рекомендации

## Результаты A/B эксперимента

| Метрика | Контроль (C) | Тритмент (T1) | Эффект | Значимо |
|--------|-------------|--------------|--------|---------|
| mean_time_per_session | 7.73 | 10.21 | **+32.12%** | Да |
| time | 8.38 | 11.34 | +35.40% | Да |
| mean_tracks_per_session | 12.78 | 15.12 | +18.33% | Да |
| sessions | 1.09 | 1.11 | +1.53% | Нет |
| mean_request_latency | 0.69 | 0.99 | +44.45% | Нет |

Тритмент побеждает по целевой метрике с p < 0.05 (t-тест Уэлча, доверительный интервал не содержит ноль).
