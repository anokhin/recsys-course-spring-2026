## Homework 2 Report

### Abstract
Основной идеей было использовать персональные рекомендации от hstu, затем
из текущей сессии выбрать якорь и с помощью предвычисленных эмбеддингов (TF-IDF + SVD) измерить, 
насколько каждый кандидат семантически близок к якорю. 
Также для разнообразия было принято решение штрафовать за рекомендации 
повторяющихся авторов.

Финальный порядок треков определяется формулой:
Score = 0.65 * semantic_score + 0.35 * hstu_rank_score - 0.05 * количество треков автора в истории

### Детали

#### Архитектура
```mermaid
[User Request]
      |
      v
[Redis History] --> (Select Anchor based on listen_time)
      |
      v
[Redis HSTU] --> (Get Candidates) --> (Filter Seen)
      |
      v
[Embeddings File] --> (Load Anchor Vector & Candidate Vectors)
      |
      v
[Scoring Loop]
   |--> Semantic Similarity (Dot Product)
   |--> HSTU Rank Decay
   |--> Artist Repetition Penalty (from Redis Catalog)
      |
      v
[Best Track ID] --> Return to User
```
#### Оффлайн: Создание эмбеддингов треков
1. Из tracks.json берем метаданные: title, artist, genres, mood, summary.
2. С помощью TfidfVectorizer преобразуем объединенный текст в разреженную матрицу
3. С помощью TruncatedSVD сжимаем полученную матрицу до размерности 128
4. Нормализуем векторы (по L2), чтобы скалярное произведение равнялось косинусному сходству.
5. Сохраняем словарь {track_id:эмбеддинг трека} в data/embeddings.joblib

#### Онлайн: Ранкинг персональных рекомендаций
1. Для каждого автора из истории прослушиваний считаем сколько его треков в истории
2. Выбор Якоря: Алгоритм выбирает один трек из истории (взвешенный рандом).
3. Получаем индивидуальные рекомендации для пользователя от hstu и фильтруем прослушанные треки
4. Считаем score для треков: 0.65 * semantic_score + 0.35 * hstu_rank_score - 0.05 * количество треков автора в истории

Размер истории пользователя - 20 треков, в качестве fallback_recommender используется lightfm.
