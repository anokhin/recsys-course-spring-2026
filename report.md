## Homework 2 Report

### Abstract

Предложен гибридный рекомендер **HSTU-Reranked**, объединяющий персонализацию HSTU и контекстуальный сигнал SasRec-I2I. Ключевая идея: возвращать трек, который HSTU считает релевантным для пользователя И который SasRec-I2I поддерживает по хотя бы одному якорю из истории сессии.

### Детали

**Два ML-сигнала:**
- **HSTU** (Hierarchical Sequential Transformer Unit) — персонализированный список ~100 треков для каждого пользователя, отражает долгосрочные предпочтения
- **SasRec-I2I** (Sequential Recommender) — контекстуальные рекомендации на основе текущей истории сессии

**Алгоритм:**
1. Загрузить HSTU-кандидатов для пользователя (set из ~100 треков)
2. Для каждого якоря в истории прослушиваний запросить SasRec-I2I рекомендации
3. Найти трек из HSTU, который SasRec также рекомендует; скор = `listen_time × (N - rank)`
4. Вернуть трек с максимальным скором (персонализированный + контекстуальный)
5. Если пересечение HSTU ∩ SasRec пустое — fallback на baseline SasRec-I2I

```
История: [(anchor_1, t1), ..., (anchor_k, tk)]
              ↓ SasRec-I2I для каждого якоря
HSTU-кандидаты ∩ SasRec-кандидаты → best by (listen_time × rank_score)
              ↓ если пусто
          SasRec-I2I baseline
```

Fallback гарантирует, что тритмент не хуже контроля в случае отсутствия пересечения.
